1. CORE STRUCTURAL FOUNDATION & TECHNOLOGY STACK
================================================================================

Q: What structure is the app based on? Is it Vanilla JS or a Framework?
A: The entire application is built on 100% MODULAR MODERN VANILLA JAVASCRIPT (ES6+ Modules)
   bundled using Vite 6. There is NO React, NO Angular, NO Vue, and NO Next.js.

Architectural Rationale for Choosing Vanilla JS:
1. Zero Framework Overhead:
   - Eliminates 150KB - 300KB of virtual DOM and framework runtime scripts.
   - Initial DOM execution and hydration completes in under 30 milliseconds.
2. Perfect Core Web Vitals Performance:
   - LCP (Largest Contentful Paint): Under 1.2 seconds on desktop and 1.8 seconds on mobile.
   - CLS (Cumulative Layout Shift): Exactly 0.00 using strict layout containment, tabular
     numeral fonts, and predefined aspect-ratio image containers.
   - FCP (First Contentful Paint): Under 0.6 seconds.
   - INP (Interaction to Next Paint): Under 50ms utilizing non-blocking event loops,
     touch-action manipulation, and lazy off-thread initialization.
3. Direct Hardware & Web Audio Access:
   - Direct native access to the Web Audio API (AudioContext, BiquadFilterNode, GainNode,
     DynamicCompressorNode) and HTML5 2D Canvas rendering without virtual DOM reconciler contention.

Tooling & Build System:
- Bundler       : Vite 6.4.3 (type: "module")
- Code Splitting: Rollup manualChunks configuration separating Firebase dependencies
                  ("firebase-vendor") from the main application ("main", "portal", "i18n").
- CSS Engine    : Native CSS3 with custom properties (--portal-gold, --heritage-gold, --glass-bg),
                  frosted glass backdrop filters, and dynamic viewport units (100dvh, 100svh).
- Image Pipeline: High-performance WebP compression generated via Node.js + Sharp.
- Hosting       : High-speed edge CDN deployment on Vercel with automatic asset compression.

3. BACKEND, AUTHENTICATION, SIGN-IN & SIGN-OUT STRUCTURE
================================================================================

3.1 Authentication Architecture (src/services/firebaseAuth.js)
Powered by the Firebase 12 Modular SDK (firebase/app, firebase/auth, firebase/firestore):

1. Google OAuth Live Popup (signInWithPopup):
   - Configured with GoogleAuthProvider and custom parameter { prompt: 'select_account' }.
   - Bound directly to user click gestures on buttons (#btn-welcome-google-signin,
     #btn-google-signin-direct, #island-google-auth-btn) to prevent popup blockers.
   - Automatically recovers and passes user credentials into the active session.

2. Google OAuth Full-Page Redirect Fallback (signInWithRedirect):
   - Graceful fallback for strict third-party cookie restrictions, Safari ITP, or in-app webviews.
   - Evaluated on startup via getRedirectResult() to restore credentials without user interaction.

3. Guest Devotee Authentication Fallback:
   - For visitors who prefer not to sign in with Google, clicking "Continue as Guest Devotee"
     generates an instant guest session UID: "guest-" + Date.now().
   - Grants full access to browse the site, submit blessings, and interact with all festival widgets.

4. Persistent Auth State Observer (onAuthStateChanged):
   - Listens to Firebase Auth state events and automatically mirrors the session into
     localStorage ("mondal_bari_auth_user").
   - Synchronizes avatar, name, and role across open tabs in real-time.

5. Sign-Out Routine (signOut):
   - Revokes Firebase tokens, deletes the session cache from localStorage, and seamlessly
     restores the UI to default visitor view without requiring a full page refresh.


3.2 Role-Based Access Control (RBAC) (src/services/rbacService.js)
The platform enforces a three-tier access control structure:

[Tier 1] ADMIN:
- Full privileges: Approve/reject/delete devotee photos, publish official Natmandir gallery items,
  create "Others by Onnota" artwork posts, update emergency festival announcements, edit ritual schedules,
  and assign roles to other users.
- Super Admin Check: debanjanmondal8996@gmail.com is hardcoded as permanent root administrator.

[Tier 2] EDITOR:
- Content privileges: Upload photos, manage story card submissions, curate festival memories.
- Assigned dynamically in Cloud Firestore collection "user_roles/{email}" with { role: "editor" }.

[Tier 3] VISITOR:
- Public privileges: Explore public festival folds, stream radio, trigger live Dhak synthesizer,
  submit community photos (stored as pending moderation), give pranam/likes, generate story cards.
- Default role assigned to all unauthenticated guests and standard signed-in devotees.

Role Verification Flow:
1. Check email against hardcoded SUPER_ADMIN_EMAIL (0ms latency fail-safe).
2. Check in-memory roleCache map.
3. Query Cloud Firestore document "user_roles/{cleanEmail}".
4. Fall back to ROLES.VISITOR.

4. DATA MANAGEMENT & DATABASE STORAGE ARCHITECTURE
================================================================================

The application implements a resilient, offline-first Three-Tier Data Strategy (src/services/contentStore.js):

Tier 1: HTML5 LocalStorage Client Cache (Instant 0ms Read)
- Keys managed:
  * "mondal_bari_auth_user"               : Active user credentials and role.
  * "mondal_bari_welcome_session_entered" : Session flag preventing repeated onboarding popups.
  * "mondal_bari_preferred_lang"          : Language choice ("en" or "bn").
  * "mondal_bari_curated_gallery_v2"      : Cached array of curated Natmandir photos.
  * "mondal_bari_curated_onnota_v2"       : Cached array of "Others by Onnota" artisan creations.
  * "mondal_bari_community_photos"        : Local devotee uploaded photos.

Tier 2: Cloud Firestore Remote Database (Cloud Sync & Multi-User Collaboration)
- Collections:
  * "gallery_posts" : Document schema: { id, title, title_bn, category, categoryLabel, src,
                      author, date, likes, isCurated, target, timestamp }
  * "onnota_posts"  : Document schema: { id, title, title_bn, category, categoryLabel, src,
                      author, date, likes, desc_bn, timestamp }
  * "announcements" : Urgent notifications broadcasted across the executive festival bar.
  * "user_roles"    : Role assignments mapped by user email address.

Tier 3: Static Seed Data Fallbacks (Zero-Network Resilience)
- If Firestore is offline or unconfigured, the application seamlessly falls back to static seed
  catalogs in src/data/playlists.js and src/data/pujoData.js.

5. STORAGE OF IMAGES & MEDIA ASSETS
================================================================================

1. Pre-Rendered Platform Assets (/public/):
   - Scenery, invitations, backgrounds, and Alpona motifs are stored locally in /public/bg/,
     /public/bg-mobile/, and /public/images/.
   - All assets are pre-compressed into WebP format (85% quality) via Sharp, cutting file size
     by up to 75% compared to PNG/JPEG.
   - Desktop screens load /bg/mondal-bari-hero.webp (1920x1080), while mobile screens load
     /bg-mobile/mondal-bari-hero-mobile.webp (768x1366, 73.5 KB) via responsive <picture> tags.

2. Audio & Album Media:
   - Songs are streamed directly through YouTube's global CDN infrastructure without hosting
     heavy multi-megabyte MP3 files on the server.
   - Track thumbnails and vinyl artwork are pulled on-demand from YouTube's edge:
     https://img.youtube.com/vi/{videoId}/mqdefault.jpg.

3. Devotee Community Photo Uploads:
   - When users drag-and-drop or select photos in the Grand Gallery upload widget, the client-side
     JavaScript downsamples the image using an HTML5 Canvas context (max dimension 1280px, WebP
     compression quality 0.82).
   - The processed image is saved as a base64 Data URL or synced directly to Firestore, preventing
     server overload and keeping payloads lightweight.

6.1 Dual Audio Engine
---------------------
The app integrates two complementary, synchronized audio systems:

System A: YouTube IFrame API Radio Manager (src/audio/youtubePlayer.js)
- Features: Plays Agomoni Puja Classics, Birendra Krishna Bhadra's Mahalaya, and Festival melodies.
- Zero Initial Impact: The 841.4 KiB YouTube IFrame API is loaded strictly on-demand on the
  user's first click or enter gesture, eliminating initial render-blocking overhead.
- Synchronization Engine:
  * startProgressTicker() polls player time at 250ms intervals.
  * Synchronizes the interactive scrubber, elapsed/remaining timecodes, rotating vinyl record,
    and the Dynamic Island equalizer wave bars.
  * Seamless track advancing: Automatically advances to the next track when a track finishes.
  * Default Track 01: Pre-configured to Track 01: "Mondol Bari Festive Ambient" (DZ21CSg22nc).

System B: Pure DSP Web Audio Drum Synthesizer (src/audio/soundEffects.js)
- Features: Physical modeling synthesizer for authentic Bengali festival percussion with 0ms latency.
- Drum Bols Synthesized:
  * "Dha" (ধা)    : Resonant low membrane strike (Sine oscillator swept from 145Hz to 58Hz, 800ms decay).
  * "Dyang" (দ্যাং) : High open rim stroke (Bandpass filtered resonant click with fast decaying harmonics).
  * "Ta" (তা)     : Sharp rim slap (White noise burst filtered between 800Hz-3.5kHz with 80ms decay).
  * "Kut" (কুত)    : Muted dead slap (Punchy center-head bandpass thud with 45ms decay).
  * "Gurgur" (গুড়গুড়): Rapid fluttering roll (Quantized pulse train with modulated micro-gain envelopes).
  * "Kanshor" (কাঁসর): Metallic brass bell ringing (Multiple inharmonic oscillators through high-Q 1850Hz filter).
  * "Shankha" (শাঁখ) : Sacred conch horn call (Complex frequency sweep with organic acoustic flutter).
- Sound Booster: BiquadFilterNode Low-Shelf (+6dB at 80Hz), Peaking filter (+4dB at 3.2kHz), and
  DynamicCompressorNode limiter for analog warmth with zero digital distortion.
